# 05 · Benchmark protocol (fair quantum vs classical comparison)

The judges award 20 points for "a classical baseline and a fair comparison". These are the rules every experiment follows.

## 1. Same problem, same objective
- All methods minimise the **identical** C(x) = q xᵀΣx − μᵀx with Σx = k, built from the same `PortfolioProblem` object.
- Methods that need an unconstrained form (penalty-QAOA, simulated annealing) use the **same** λ = `default_penalty()`.
- Quality is always scored on C(x) of the returned *feasible* portfolio, never on the internal energy.

## 2. Baselines
| Baseline | Role | Settings |
|---|---|---|
| Random feasible guess | floor | P(opt) = 1/C(n,k), analytic |
| Brute force | ground truth + ceiling | enumerates all C(n,k) feasible strings |
| Greedy | "what an analyst does in Excel" | add the asset with the best marginal C until k are chosen |
| Simulated annealing | strong general-purpose heuristic on the same QUBO | `sa_sweeps` from config, geometric temperature schedule, 100 reads; report P(opt) over reads |

Simulated annealing is the *fair* heuristic comparator because, like QAOA, it is a sampler over the same QUBO. Its P(optimal) is directly comparable.

## 3. Instances
- **Real-data instance (headline):** the 6 NSE tickers in config, k = 3, q = 0.5.
- **Robustness set (≥ 20 instances):** random 6-asset subsets of a 10-ticker universe × q ∈ {0.25, 0.5, 1.0}. Seeds are fixed. Report **mean ± std** and the share of instances where top-1 is optimal.
- **Hardware instance:** 4 tickers, k = 2 (shallow enough for current devices).

## 4. Metrics (definitions in 03 §5)
**Headline (always reported side by side):** P(optimal), **approximation ratio** and **P(top-2 baskets)**, each next to its
uniform-random reference (1/C(n,k), the random-basket AR, 2/C(n,k)). Reason: on the real NSE instance the optimum and runner-up
differ by only 0.004 in cost, so P(optimal) alone is fragile to a near-tie (see 01_SPEC AC5).

Also reported: P(feasible), P(optimal | post-selected), top-1-is-optimal, wall time, objective evaluations / circuit executions.

## 5. Timing honesty
- Report wall time for **everything**, including QAOA parameter optimisation (statevector), not just sampling.
- State clearly: *"Statevector simulation time is not quantum runtime. On hardware, cost is dominated by queueing and shots."*
- The scaling slide uses **search-space size and gate counts**, not extrapolated speed-ups.

## 6. What we must say out loud
1. Brute force is exact and fastest at this size.
2. Simulated annealing reaches the optimum with high probability at this size.
3. XY-QAOA's value here is that it is **far better than penalty-QAOA and random**, and that it keeps 100% feasibility, which also gives error detection on hardware.
4. No quantum advantage is claimed or implied.
